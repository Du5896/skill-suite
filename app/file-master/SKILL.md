# 全能文件处理中心（File Master）

专业级文件处理技能：既能**预览**各种文件，也能**创建/编辑**各种文件，产出质量对标专业工具水准。本技能内置五个专业级子技能，AI 根据用户当前要求和实际情况**智能选择**对应的内置技能来执行。

## 智能路由（先判断，再执行）

拿到用户请求后，先按下表判定应使用哪个**内置子技能**，然后 **Read 对应内置技能的 SKILL.md** 再按它的流程执行：

| 用户要求 | 内置技能 | 说明 |
|---|---|---|
| 查看 / 预览 / 读取文件：Excel（.xlsx/.xls）、PPT（.pptx）、Word（.docx）、PDF、CSV、文本、图片 | `bundled/file-preview` | 先运行其 `scripts/preview.py` 把内容真实解析出来，再转成用户易读的展示；不猜、不编造 |
| 创建 / 编辑幻灯片（做 PPT、新建演示文稿、修改已有 Slides） | `bundled/ppt` | 走飞书幻灯片流程：理解需求 → 选设计系统 → 逐页闭环（lint 校验）→ 回读验收 → 交付链接/导出文件 |
| 起草 / 修订商业合同（采购、服务、营销、工程施工、软件许可、租赁、保密等） | `bundled/doubao-contract-drafting` | 读题干与附件 → 交易信息拆解 → 起草 → 生成 Word → 依次跑校验门禁（preflight / consistency / policy / font）→ 交付 |
| 创建 / 编辑 Word 文档（公文、正式文书、教案、学习材料、报告等；或用户提供 DOCX 要求修改） | `bundled/word` | 走 Word 技能流程：场景路由 → 新建（模板/无模板）或编辑 → 内容规划 → 生成 → audit 校验 → 交付 .docx。Word 产物大多严肃场景，除非用户明确要求否则禁 emoji |
| 去 AI 味 / 降 AI 味 / 润色 / 改写得更自然（任何文本、文章、回复） | `bundled/humanizer` | 按它的检测与修复清单处理：AI 高频词、过度结构化、机械化句式等 |

**判断规则**：
- 同时命中多个需求（如"先预览这份合同再帮我润色"）→ 按顺序依次调用对应内置技能，前一个完成后再进入下一个。
- **Word 与合同的边界**：起草/修订商业合同走 `bundled/doubao-contract-drafting`；其他 Word 文档（公文、教案、报告、普通文书、修改用户给的 DOCX）走 `bundled/word`。
- 无法唯一判定时，优先按用户的核心动词判断（看=预览，做/写=创建）。
- 判定后**必须 Read 对应内置技能的 SKILL.md 全文**再动手，禁止凭本文件摘要或记忆直接执行；内置技能的 references/scripts 均以其自身路径为准（相对本技能为 `bundled/<技能名>/...`）。

## 质量铁律（专业标准，必须遵守）

1. **预览不编造**：文件内容必须来自 `bundled/file-preview/scripts/preview.py` 的解析结果；解析失败如实报告，绝不猜测行数、页数、文字。
2. **创建即成品**：PPT、合同、文章等创建产物必须达到可直接交付/使用的标准，不允许交半成品、模板壳或占位内容。
3. **内置技能流程完整走**：PPT 必须逐页写入并 lint 校验、回读验收；合同必须跑完全部校验门禁；润色必须按 humanizer 的清单逐项修复。不得为了快而跳过子技能的验证步骤。
4. **子技能铁律继承**：各内置技能 SKILL.md 里的铁律（如 PPT 禁 emoji、合同不编造主体金额、humanizer 的修复清单）同样适用于本技能执行时。
5. **失败如实报告**：任何一步失败（如缺库、缺素材、校验不过），说明原因和已尝试的修复，不假装成功。

## 执行骨架

1. **路由**：按上表判定本次用哪个/哪些内置技能。
2. **读取**：Read 对应内置技能的 SKILL.md（完整读完，尾部常有重要信息）。
3. **执行**：按该内置技能的流程逐步执行，每步完成后确认再进下一步。
4. **交付**：按该内置技能的交付规范交付（预览 → 展示解析结果；PPT → 交付幻灯片链接/导出文件；合同 → 交付 Word 文件+说明；润色 → 交付润色后文本）。

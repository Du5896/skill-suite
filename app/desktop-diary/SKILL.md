# 桌面日记 desktop-diary

把"每次任务都记一笔"变成强制默认行为：**每个任务收尾时先记日记，再给用户回复**。

## 触发时机（每次任务都会做）

以下任一情况命中即执行本技能：

1. **任务收尾**：用户请求已基本完成、准备输出最终回复前——先写一条日记，再回复。无论任务大小（信息查询除外，纯问答可不记，避免噪音）。
2. **关键词触发**：用户说"写日记 / 记笔记 / 做笔记 / 记事本 / 空闲 / 记录一下 / 今天干了啥 / 给我记一笔"等。
3. **用户明确点名**：用户直接说"用桌面日记技能"或"记到桌面"。
4. **定时任务**：由定时任务触发时，记录定时任务本身的内容（如提醒、巡检结果）。

## 执行流程

### Step 1 探测桌面路径

优先用脚本探测（见 Step 3），脚本不可用时按以下顺序人工判定：

- **Windows**：`$env:USERPROFILE\Desktop`；若存在 `$env:USERPROFILE\OneDrive\Desktop`（或 `$env:USERPROFILE\OneDrive - <组织名>\Desktop`）且桌面文件实际存于该处，优先用 OneDrive 桌面。
- **macOS**：`~/Desktop`（`$HOME/Desktop`）。
- **Linux**：`~/Desktop`；不存在则用 `$HOME`。
- 判定后确认目录存在；不存在则创建（仅桌面缺失时，不要乱建目录）。

### Step 2 确定日记文件

- 文件名：`日记-YYYY-MM-DD.txt`（按天一个文件，日期取用户本地时间，用工具取当前日期，禁止自行推算）。
- 当天文件已存在 → **追加**；不存在 → **创建**。
- 追加规则（防覆盖铁律）：**必须先 Read 完整现有内容，再在末尾拼接新条目，用 Write 整体回写**。禁止只写新条目覆盖旧内容。

### Step 3 写入日记条目

**推荐方式：运行辅助脚本**（确定性高、处理编码和路径）：

```
python "scripts/diary.py" --title "任务名/主题" --summary "一句话摘要" --mood "心情词（可选）"
```

脚本会自动：探测桌面 → 按天建/追加文件 → 按 emoji 模板写入 → 输出最终文件路径。

**脚本不可用时手工写入**，模板如下（emoji 表情风格，每条约 3-5 行）：

```
📅 2026-09-24 星期四

🕒 14:32 · ✅ 完成「给用户做了 XX」
📝 摘要：简要记录做了什么、关键结果
😊 心情：满足 / 开心 / 累并快乐着
```

- 条目间用 `────` 分隔线隔开，便于阅读。
- emoji 按内容选：任务完成 ✅ / 进行中 ⏳ / 收获 🎉 / 记录 📝 / 时间 🕒 / 日期 📅 / 心情 😊😐😮💨。
- 内容只写**事实摘要**，不写隐私敏感信息（密码、密钥、身份信息等）。
- 摘要来自本任务实际执行内容，禁止编造未发生的事。

### Step 4 确认与收尾

- 脚本运行后回读文件尾部，确认条目已写入、无乱码、无覆盖旧内容。
- 向用户回复时提一句："📝 已记入桌面日记"，不必展示全文（除非用户要求）。

## 边界与降级

- 纯信息问答（用户只问概念、一句话闲聊）不强制记录，避免日记噪音；但用户明确要求记时仍记。
- 桌面路径探测失败且无法创建 → 记到项目目录 `日记-YYYY-MM-DD.txt` 并在回复中说明位置。
- 写入失败（权限/磁盘满）→ 不阻塞主任务，回复中说明"日记未写入 + 原因"。
- 用户说"今天先不记/别记了" → 本轮跳过，不追问。

## 常见问题

- **日记文件在哪里？** 桌面根目录 `日记-YYYY-MM-DD.txt`，每天一个新文件。
- **想改文件名或目录？** 对脚本加参数 `--dir <目录>` `--prefix <文件名前缀>`；或告诉用户手动指定。
- **想看历史日记？** 技能被触发时读取桌面对应日期文件并回述要点。

# 动画与 UI 设计落地（UI & Animation Designer）

**定位**：animation-ui-master 的**设计执行子技能**。主技能负责"找方案"（资料库/表格），本子技能负责"做出来"——把选中的动画与 UI 方案**真正设计并打入界面**，产出可运行作品。

## 设计四件事（先确认）

1. **做什么**：UI 类型（网页/App/仪表盘/海报/组件等）与界面位置清单（启动页、导航、按钮、表单、弹层、转场、加载、内容展示等）
2. **什么触发时机**：load / hover / focus / active / state-change / scroll-into-view / route-change / gesture / audio-driven
3. **什么风格**：品牌 / 科技 / 可爱 / 简约 / 用户指定
4. **交付载体**：HTML / CSS / GSAP / 设计稿

## 设计流程（按此执行）

### 第 1 步 · 理解需求
明确上面四件事；把界面涉及的所有位置列成"落点清单"。

### 第 2 步 · 取方案
- 主技能已给方案 → 直接用（编号、效果描述、参数）。
- 未给 → 从 animation-ui-master 的资料库检索（application-map.csv 按界面位置/触发时机、animation-library.csv 按效果）或按用户表格内容取。
- **来源必须明确**：方案来自资料库 / 用户表格 / 两者组合，缺一不可。

### 第 3 步 · 组合编排（动效纪律）
- 主次分明：一个界面位置一个主动画，辅助动画不抢戏；同屏并发 ≤ 6（移动端）
- 时长分级：即时 80-120ms｜微反馈 160-260ms｜状态过渡 280-400ms｜转场 400-600ms｜入场 600-800ms
- 缓动：入场 `cubic-bezier(0.22,1,0.36,1)`｜标准 `cubic-bezier(0.4,0,0.2,1)`｜退场 `cubic-bezier(0.4,0,1,1)`｜回弹 `cubic-bezier(0.34,1.56,0.64,1)`
- 错峰：密集 30-50ms｜标准 60-120ms｜舒缓 150-250ms
- 性能红线：只动 transform/opacity/filter；滚动用 rAF + IntersectionObserver
- 打断续接：从当前计算值续接，禁止跳回初始帧

### 第 4 步 · 打入界面（真实落地）
把每个方案**实际写进作品**：
- 动画 → 挂到对应界面元素上（按钮 hover、卡片入场、弹层进出、转场等），能加就加
- UI 规范 → 套用到组件（配色/间距/圆角/层级/玻璃拟态等）
- 效果描述 → 转成可运行代码（CSS keyframes / transition / GSAP / JS）
**不是"提到"，是让动画和 UI 真实出现在作品里。**

### 第 5 步 · 交付 + 自查
交付可运行作品（HTML/CSS/GSAP 代码带注释可直跑，或设计稿）。交付前自查：
- 落点清单每个位置的动画都打进去了吗？
- 有遗漏 → 补上再交付。
- 标注每个动画的来源（资料库编号 / 表格条目 / 组合定制）。

## 铁律

1. 方案必须有来源，不凭空发明。
2. 能加就加：合适的位置全部加动画，不留"死板不动"的角落。
3. 性能与无障碍：只动 transform/opacity/filter；尊重 prefers-reduced-motion（降级淡入）。
4. 交付真实可运行的作品，不是口头描述。

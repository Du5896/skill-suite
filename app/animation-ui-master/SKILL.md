# 动画与 UI 设计大师（Animation & UI Master）

基于完整动画资料库 + 内置双子技能的极致动效设计引擎。库中数据来自《动画大全》：
- **1707 条**动画类型百科（40 个大类：基础变换/不透明度/遮罩裁剪/转场/文字/SVG路径/粒子/3D/滤镜/加载/物理弹簧/滚动/指针/数据可视化/表单/状态/角色/相机/游戏/动画原理/风格化/音频/缓动函数/Preset/影视转场/动态图形/图标/表情/材质/自然/程序化/ARVR/工业/营销/教学/平台/属性/面部/音乐/微交互）
- **9205 条**界面应用映射（12 大界面分类 × 界面位置 × 触发时机 → 动画方案，含三档时长/缓动曲线/实现方式/降级策略/优先级/动效坐标）
- **43 条**动效 Token 规范（时长档位/缓动曲线/位移距离/错峰节奏/触发模型/物理参数/性能红线/工程约定）

**调用本技能 = 直接基于这套专业资料库做设计，不再凭空发挥。**

## 智能路由（先判断，再执行）

拿到用户请求后，先按下表判定走哪条路，再 **Read 对应内置子技能的 SKILL.md** 按它的流程执行：

| 用户请求 | 路由 | 说明 |
|---|---|---|
| 用户**给了表格/文件/内容**（动画表、UI 规范表、素材清单等），要求做动画/UI、把内容打进去 | ① `bundled/animation-ui-table`（先吃表格：完整看完所有内容、不机动话、能加就加）→ ② `bundled/ui-animation-designer`（设计落地：把选中的动画/UI 真正打入界面） | 两个子技能配合：先吃表格，再设计打入 |
| 用户**只说设计**（设计 UI / 动画 / 动效，没给表格） | 本技能**资料库主流程**（下方第 0~6 步）→ `bundled/ui-animation-designer`（设计落地） | 先全库通读，再按资料库设计 |
| 用户给了表格 + 又要自定义独特方案 | ① `bundled/animation-ui-table`（吃表格）→ 在其基础上做自定义定制（底子必须是表格内容）→ ② `bundled/ui-animation-designer` | 自定义方案基于表格定制，不脱离表格 |

**两个内置子技能（必读）**：
| 子技能 | 路径 | 何时读 |
|---|---|---|
| 表格驱动（吃表格） | `bundled/animation-ui-table/SKILL.md` | 用户给了表格/内容时，动手前必须完整读完它 |
| 设计落地（打入界面） | `bundled/ui-animation-designer/SKILL.md` | 每次设计执行前必须完整读完它 |

## ⚡ 两条最高优先规则（一进来就遵守，凌驾于其他所有规则）

### 规则一：先完整看完表格里的所有内容，再动手！
无论走哪条路由，**涉及用户提供的表格/内容时，第一步必须完整读完用户给的所有内容**——逐行逐条读完每一行每一列，不能抽样、不能跳读、不能只看表头、不能只读前几行就假装看完。未看完之前，禁止开始设计、禁止输出任何动画方案。

### 规则二：能有动画的地方，就要有动画！
这是全技能最重要的提醒，用感叹号强调——**能给界面加动画的地方，就一定要加动画！** 读完资料库后，你首先要知道"**哪里适合有动画**"：以 `application-map.csv`（9205 条界面应用映射）为权威依据，12 大界面分类（启动与窗口、导航与菜单、弹层与反馈、按钮与操作、表单与输入、状态与数据、内容展示、媒体与画布、指针与装饰、滚动与容器、转场与路由、系统级）下的每个界面位置、每个触发时机，都是**适合有动画的地方**。设计任何 UI/页面时，逐位置检查"这里能不能加动画"，能加就加，不给界面留下"死板不动"的角落！只有明确不适合动画的极少数场景（如纯静态截图、无障碍降级已触发）才能不加，且必须说明原因。

## 设计工作流（七步，按顺序执行）

### 第 0 步 · 全库通读（强制，不可跳过）
按上表顺序，把 `references/` 下 5 个文件**全部完整读完**，其中两个表格 CSV **逐行逐条看完所有内容**（9205 条应用映射 + 1707 条动画百科，一条不漏）。读完后再开始下一步。这一步的目的是：让你**先知道哪里适合有动画**（应用映射表）、**知道每种动画怎么做**（动画百科）、**知道时长缓动基准**（Token 规范）。
**通读自检（必须通过才算读完）**：读完必须能准确回答 ①库里有哪些大类、各自什么用途？②某界面位置（如启动页闪屏、按钮 hover、表单校验失败）适合哪些动画？③时长档位与缓动曲线的基准值？答不上来 = 没看完，回去继续读完。

### 第 1 步 · 理解需求 + 定位动画落点
明确四件事：**做什么界面/组件**（如按钮、卡片、页面转场）、**什么触发时机**（load / hover / active / state-change / scroll-into-view / route-change / gesture / audio-driven）、**什么风格**（品牌、科技、可爱、简约）、**交付载体**（CSS / GSAP / Canvas / 设计稿）。
同时**逐位置盘点**：把需求涉及的所有界面位置列出来，对照 `application-map.csv` 通读时掌握的映射，标出"每个位置适合什么动画"——这是"哪里有动画"的落点清单。

### 第 2 步 · 复核 Token 基准
通读已掌握，此处只做复核确认：
- 时长档位：即时 80-120ms｜微反馈 160-260ms｜状态过渡 280-400ms｜转场 400-600ms｜入场 600-800ms
- 缓动：入场 `cubic-bezier(0.22,1,0.36,1)`｜标准 `cubic-bezier(0.4,0,0.2,1)`｜退场 `cubic-bezier(0.4,0,1,1)`｜回弹 `cubic-bezier(0.34,1.56,0.64,1)`｜弹性 `cubic-bezier(0.68,-0.55,0.27,1.55)`｜循环 `linear`
- 位移：微距 4px｜中距 8-16px｜长距 24-32px
- 错峰：密集 30-50ms｜标准 60-120ms｜舒缓 150-250ms

### 第 3 步 · 按场景取方案（应用映射）
对照第 1 步的落点清单，从已通读的 `application-map.csv` 中取每个界面位置对应的动画方案。命中条目直接给出：动画类型、三档时长（紧凑/标准/舒展）、缓动曲线、实现方式、**降级策略**、**优先级（P0 必做 / P1 建议）**、动效坐标。同界面位置下多个候选 → 按优先级与场景挑选 1 个主动画 + 可选辅助动画。**能加动画的位置，必须给到位，不允许留空白。**

### 第 4 步 · 按效果取实现（动画百科）
从已通读的 `animation-library.csv` 中取第 3 步所选动画类型的效果描述与实现方式；需要组合多个效果时逐一确认，禁止凭印象编造实现。

### 第 5 步 · 组合编排（做出"极致"）
把查到的方案组织成完整动效设计：
1. **主次分明**：一个界面位置一个主动画，辅助动画不抢戏；同屏动画密度遵循 Token（移动端并发 ≤ 6）
2. **时长分级**：按触发性质套档位（悬停用微反馈 160-260ms，转场用 400-600ms）
3. **缓动统一**：同一组件进出一致；进出场同一变换空间，方向/距离一致
4. **错峰编排**：多元素按密集/标准/舒缓错峰，避免同时起跑
5. **性能优先**：只动 `transform` / `opacity` / `filter`，禁止动画 width/height/top/left；滚动用 rAF + IntersectionObserver，禁止 scroll 内同步读布局
6. **降级与无障碍**：`prefers-reduced-motion` 时关视差/弹簧/自动播放，仅留淡入；按总表降级策略兜底
7. **打断续接**：动画被打断时从当前计算值续接，禁止跳回初始帧

### 第 6 步 · 产出交付
按用户要求交付**可运行**结果：CSS/GSAP/Canvas 代码（带注释、可直接跑）、或 UI 动效设计规范（界面位置、触发、时长、缓动、实现、降级逐项列出）、或含动效的 HTML 页面。交付时注明每个动画对应的库编号（TYP-XXXX / ANM-XXXXX），可溯源。交付后自查一遍：**凡是适合动画的位置，动画都给到位了吗？有遗漏就补上！**

## 铁律（必须遵守）

1. **先全库通读**：调用后必须完整读完 `references/` 全部 5 个文件，未读完不得开始设计。
2. **先读完用户给的表格**：用户提供了表格/内容时，先完整读完再动手（见智能路由与规则一）。
3. **不机动话**：用户给了表格时，不脱离表格临场凭空发挥；表格里合适的内容全部打进去，能加就加。
4. **能有动画的就要有动画！**：逐位置检查，能加动画就加，不给界面留"死板不动"的角落；只有极少数不适合动画的场景才不加且必须说明原因。
5. **数据不编造**：动画条目、时长、缓动、实现方式必须来自资料库或用户表格；没有的条目不硬凑，如实说明。
6. **性能红线**：只动 transform/opacity/filter；移动端并发动画 ≤ 6；滚动节流。
7. **无障碍优先**：尊重 `prefers-reduced-motion`，提供降级路径（淡入）。
8. **编号溯源**：交付动效可标注 TYP-XXXX / ANM-XXXXX（资料库）或表格条目编号，便于核对。
9. **风格贴合需求**：品牌/科技/可爱等风格决定缓动与粒子密度，不默认套一种模板。

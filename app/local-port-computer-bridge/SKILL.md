# 单人本地端口电脑桥接（Local Port Computer Bridge）

**用途**：让你在**普通对话模式**（或任何不能直接操作电脑的 AI）下，也能通过固定指令操作自己的电脑——不用占用工作模式的电脑操作额度。

**原理**：你电脑上运行一个本地桥接服务（`scripts/bridge_server.py`，监听 `127.0.0.1:58201`）。AI 按本技能规范输出标准指令 → 服务收到指令 → 在本机执行（打开文件、运行程序、复制文件、弹窗等）→ 返回执行结果。

## 适用范围（先说清楚，再谈用法）
- 本技能只能操作**桥接服务所在的那台机器**：AI 与 `bridge_server.py` 必须**在同一台电脑上**通过 `127.0.0.1` 回环通信。
- **云电脑 / 云沙箱 / 远程服务器 / 容器等环境天然不适用**——那些环境里的 `127.0.0.1` 是云主机自己的回环地址，不是你的电脑，端口必然不可达。
- 唯一成立条件：把 `bridge_server.py` 部署并运行在**目标电脑本机**上，且 AI 也在同一台机器（或其回环可达的环境）运行。

## 端口（已确认可用）
- 地址：`127.0.0.1`（仅本机回环，**禁止**绑定 0.0.0.0、禁止外网访问）
- 端口：`58201`（初始化时已检测空闲）

## 使用前置与环境自检（每次使用前强制执行）
1. **探测端口**：AI 先探测 `127.0.0.1:58201` 是否可达：
   - 有终端执行能力 → 运行 `python -c "import socket; socket.create_connection(('127.0.0.1',58201),timeout=3); print('OK')"`（或 `curl telnet://127.0.0.1:58201`）
   - 无终端执行能力 → 直接询问用户："桥接服务是否已在你电脑上启动？（运行 `python bridge_server.py`）"
2. **结果判定**：
   - **可达** → 继续下面的使用流程。
   - **不可达** → **不要发任何指令**，明确告知用户："**桥接服务未运行，或当前环境不是桥接服务所在的本机。**"并按下方排障指引处理。

## 排障指引（区分两种失败）
| 现象 | 原因 | 处理 |
|---|---|---|
| 在你电脑本机上探测 58201 不通 | 服务没启动 | 在你电脑上运行 `python bridge_server.py`，看到"桥接服务已启动，监听 127.0.0.1:58201"后重试 |
| 当前环境是云电脑 / 远程 / 容器，探测 127.0.0.1:58201 不通 | 不在同一台机器 | 本技能只能在**桥接服务所在的那台机器**上用；请在目标电脑本机操作，或把 `bridge_server.py` 部署到目标机器再运行 |
| 想确认服务是否在线 | —— | 在你电脑本机运行：`python -c "import socket; socket.create_connection(('127.0.0.1',58201),timeout=3); print('在线')"`，输出"在线"即服务正常 |

## 指令格式（AI 必须严格按此输出）

`类别|动作|参数1|参数2`

### 文件类（file）
| 动作 | 格式 | 示例 |
|---|---|---|
| 新建文件夹 | `file|create_folder|路径` | `file|create_folder|D:\资料\新文件夹` |
| 打开文件/文件夹 | `file|open|路径` | `file|open|C:\Users\HP\Desktop` |
| 复制文件 | `file|copy|源|目标` | `file|copy|C:\a.txt|D:\b.txt` |
| 移动文件 | `file|move|源|目标` | `file|move|C:\a.txt|D:\a.txt` |
| 删除文件/文件夹 ⚠️高危 | `file|delete_file|CONFIRMED:|路径` | `file|delete_file|CONFIRMED:C:\tmp\old.txt` |

### 程序类（app）
| 动作 | 格式 | 示例 |
|---|---|---|
| 运行程序 | `app|run|程序路径或命令` | `app|run|notepad` |
| 结束进程 | `app|close|进程名` ⚠️高危 | `app|close|CONFIRMED:notepad.exe` |

### 系统类（sys）
| 动作 | 格式 | 示例 |
|---|---|---|
| 弹窗提示 | `sys|msg|文字` | `sys|msg|任务完成啦！` |
| 写入剪贴板 | `sys|clipboard_write|文本` | `sys|clipboard_write|你好，AI` |

## 使用流程（AI 按此执行）

1. **环境自检（强制第一步）**：按上方"使用前置与环境自检"章节先探测 `127.0.0.1:58201`。**未探测或探测不可达，禁止输出任何指令**；不可达时明确告知"桥接服务未运行，或当前环境不是桥接服务所在的本机"，并给出排障指引。
2. **接收需求**：听清用户要操作什么（打开哪个文件、运行什么程序、做什么操作）。
3. **高危识别**：涉及**删除、覆盖、结束进程、修改系统**等破坏性操作 → **先向用户复述将执行的操作并请求确认**，用户明确回复"确认"后，指令参数里加 `CONFIRMED:` 标记再输出。
4. **输出指令**：按上表格式输出**一条**标准指令（一行文本，用代码块包裹，方便用户复制/服务解析）。
5. **告知结果**：把服务返回的执行结果转述给用户；失败时给出原因和下一步建议。

## 安全约束（铁律）

1. **仅限本人**：本技能只服务技能拥有者（用户本人），不替任何第三方执行电脑操作。
2. **仅回环通信**：任何情况下不得把端口开放到局域网/公网，不得使用 0.0.0.0。
3. **高危必须确认**：删除、覆盖、结束进程等破坏性操作，AI 必须先获得用户明确"确认"；指令中必须带 `CONFIRMED:` 标记，服务端无标记会直接拒绝。
4. **不主动扩大范围**：只执行用户明确要求的操作，不顺手做额外的文件修改、系统改动。
5. **日志留痕**：服务自动把收到的指令和执行结果写入 `bridge_log.txt`（在服务启动目录），出现问题可追溯。
6. **不做平台破解**：本技能只是换一条本地通道操作电脑，**不破解、不绕过任何平台的调用额度**。
